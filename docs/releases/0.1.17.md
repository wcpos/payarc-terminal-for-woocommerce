# 0.1.17

## Fixed

- **A paid order could be completed twice, reducing stock twice.** The POS
  status check and the PayArc callback can both see the same approved payment
  within a second of each other. Each loaded the order while it was still
  unpaid, so the second to run marked it paid again and WooCommerce reduced
  stock a second time. Completion now takes a per-order claim and re-reads
  the order from the database before deciding, so the second request sees the
  order already paid and leaves it alone. A status check or cancel that runs
  after the callback has completed the order now answers "approved" instead
  of contacting PayArc or the terminal again.
- The per-order lock that keeps the callback, status checks and cancels apart
  is now atomic, and a request can no longer release a lock that another
  request holds.
